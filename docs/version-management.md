# DailyFlow 版本管理规则

1. main仅保存通过独立验收的稳定源码；初始来源为真实0.5.0验收源码ZIP。
2. develop/0.6.0-reminders从0.5.0稳定提交分出，再提交真实0.6.0增量。未通过独立审计，不得合并main。
3. 仅创建稳定标签v0.5.0，指向实际0.5.0源码提交；不创建v0.6.0正式标签，不发布Release。
4. 不伪造早期版本提交，不移动旧标签，不强制推送，不删除远程分支或既有仓库。
5. 每个功能或修复采用有实际意义的提交。采用现有且经用户确认的作者身份，不修改全局Git配置。
6. 每个正式版本执行完整测试、Lint、APK构建、包名/版本/权限/签名核验，保存APK及源码ZIP哈希。
7. 开发侧成功不代表独立审计通过。审计问题必须记录，不能把B写为待审或已通过。
8. 源码ZIP与Git源码逐文件对应；必要的仓库README、安全.gitignore及版本管理文档变更单独说明，不修改业务代码。
9. 原始项目、历史APK/ZIP、测试报告、审计报告和校验文件长期保留，GitHub上传不授权清理它们。
10. 只向经认证检查无冲突的目标仓库提交。DailyFlow已按用户2026-10-31授权公开，不能据此更改其他仓库的可见性。发现未知提交、non-fast-forward或同名仓库即停止；禁止任何强制覆盖。

上传前的最终检查仍必须包括真实Git索引文件清单、敏感信息复扫、作者和账号、仓库不存在/可见性、普通push以及远程只读复核。执行结果以实际提交、分支、标签及远程核验记录为准。
