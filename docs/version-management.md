# DailyFlow 版本管理规则

main 保存独立审计通过的稳定源码，v0.5.0 与 v0.6.0 分别定位真实验收版本。标签一旦发布不移动，不删除既有分支、标签、提交或仓库，不强制推送，不回填虚构开发历史。

0.6.0 的原始候选、首次审计 B、audit-fix1 与第二轮审计 A 必须在历史和 [验证说明](verification-v0.6.0.md) 中区分。开发侧通过不能代替独立验收；独立审计专用测试与交付测试分别计数。

每次归档先核对账号、仓库、远程最新提交和祖先关系，检查实际索引、差异、源码基线及敏感内容，再用普通快进推送。未知提交、标签冲突或 non-fast-forward 时停止，不覆盖他人的工作。

本仓库按用户2026-11-03最新答复保持 Public。该选择不授权修改其他仓库可见性或上传敏感内容。APK/AAB、ZIP、用户库、私钥、认证文件、缓存、build、本机配置和第三方专有材料不纳入源码提交；原 Gradle Wrapper 保留。

仓库所需的README、安全.gitignore、版本管理与验证文档可在独立归档副本调整，必须说明与验收源包的文档差异；业务源码、资源、依赖、Schema、迁移和交付测试须对应验收基线。使用已核实的现有作者身份，不修改全局Git配置。

原始工程、每个版本的 APK/源码 ZIP、完整测试与独立审计证据、本地历史 Git 长期保留。GitHub 归档不授权清理这些文件，不自动合并未审计内容或进入下一阶段。
