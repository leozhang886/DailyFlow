# 0.6.0 提醒使用说明

1. 新建/编辑任务，在本地提醒区主动打开开关。普通任务可选择本地提醒日期/时间；过去时间会提示并阻止新设置保存。标题备注单独编辑保留原提醒。
2. 重复任务编辑先选择“仅这一天”或“整个系列”。系列在每个有效实例当天指定时间提醒；单日可改日期/时间或关闭。系列关闭全部提醒的按钮会清除本系列提醒覆盖，界面明确写出范围，不删除任务。
3. 任务详情与列表显示等待、关闭、过期、已结束或发送状态。完成/删除取消相关提醒；撤销完成仅恢复尚在未来且未投递的实例。恢复单日任务例外和修改重复规则后会重新计算。
4. 首次主动开启且通知缺失时，先说明再请求通知权限；拒绝保留配置。通知设置与精确闹钟设置是两个独立入口。精确权限未给时采用非精确调度，可能延迟，不承诺准点。
5. 点击通知进入其taskId/任务日期对应详情；已完成、删除或不再有效时安全提示。清除通知不删除任务。通知渠道可在系统设置中独立管理。
6. 应用正常退出/系统回收后由系统闹钟广播处理；重启、升级、系统时间/时区变化会重算提醒。用户强制停止期间系统限制不可绕过。重新打开后恢复未来配置，不扫描补发全部历史；若仍有持久化待投递记录，可在24小时迟到窗口内恢复，过窗不再重试。

日期/时间随设备当地时区，不是固定UTC时间。普通提醒保存相对任务日期偏移；任务日期移动时提醒日期随之移动。夏令时不存在的时刻顺延到有效时刻，重复时段取较早偏移且同一实例不重复。
系统省电、Doze以及厂商后台、自启动和后台本地通知策略可能限制唤醒/显示。小米后台本地通知有额外管理规则；本项目不接小米推送、不绕过安全设置，必要时由用户在系统应用设置核查权限。本项目没有真机验证，不保证具体澎湃OS构建的后台可达性。
已成功投递的同一实例默认不再次提醒；后台回调延迟超过24小时不补发。发送记录CLAIMED在进程崩溃窗口可能显示待核实，详见 [实现限制](phase2g-implementation.md)。
